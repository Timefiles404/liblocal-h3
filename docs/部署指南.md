# Liblocal 生产机部署指南

面向 Windows + NVIDIA 的本地 MiniMax H3 生成画布。全文假设目标机器是全新环境，
按顺序执行即可；每一步都给出「怎么验证做对了」，不要跳过验证直接进下一步。

---

## 0. 目标机器与前置条件

参考生产配置（本指南按此校准）：

| 部件 | 规格 | 对部署的影响 |
|---|---|---|
| 显卡 | RTX 5080 16GB（Blackwell, SM120） | 支持 NVFP4 原生计算，这是速度的前提 |
| CPU / 主板 | 华硕 TUF B860M-PLUS WIFI | 无特殊要求 |
| 内存 | 64GB DDR5-6000（32G×2） | ≥56GB 时权重可常驻内存，省下重复加载 |
| 系统盘 | 宏碁 GM9000 1TB NVMe | 模型约 36GB，建议单独留 80GB 以上 |
| 系统 | Windows 10/11 64 位 | — |

**硬性前置条件（不满足会直接影响能否跑或跑多快）：**

1. **NVIDIA 驱动 ≥ 580**。低于 580 时 `comfy_kitchen` 的 CUDA 13 内核无法启动，
   表现为模型全部加载完成后在采样中途报
   `detect_k_anchor kernel launch failed: CUDA driver version is insufficient`。
   程序会自动回退到 PyTorch 注意力（能跑，但明显更慢）。
   验证：`nvidia-smi` 输出的 Driver Version ≥ 580.xx。
2. **磁盘剩余 ≥ 80GB**（模型 36GB + 运行时 4GB + 输出余量）。
3. 若需要联网下载模型：可访问 ModelScope（魔搭）。

> **为什么强调驱动**：这是本项目唯一一个「不改代码就能拿到的大幅提速」。
> 其余参数都已由程序按硬件自动选择。

## 1. 拷贝项目

整个 `D:\Projects\Liblocal` 目录是自包含的（含独立 Python、venv、ComfyUI、模型），
直接整体拷贝到生产机即可，**不依赖系统 Python、不依赖 Node 运行时**。

推荐放在数据盘根部附近，路径尽量短、不含空格与中文：

```
D:\Liblocal\
```

拷贝方式任选其一：

- 移动硬盘 / 局域网共享直接复制（36GB 模型走 USB3.0 约 15–25 分钟）；
- 或只拷贝代码，模型在目标机重新下载（见第 3 步）。

---

## 2. 修复路径（**拷贝后必做**）

venv 内部记录了创建时的绝对路径。换机器或换盘符后必须修复，否则
`python.exe` 会直接报错退出。

```powershell
cd D:\Liblocal
powershell -ExecutionPolicy Bypass -File scripts\repair-runtime.ps1
```

该脚本做三件事：重写 `runtime\venv\pyvenv.cfg` 的 `home`、重建
`runtime\python\cpython-3.12-windows-x86_64-none` 这个 junction、修正
`activate*` 脚本里的旧路径。

**验证：**

```powershell
.\runtime\venv\Scripts\python.exe -c "import torch;print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

期望输出类似 `2.11.0+cu128 True NVIDIA GeForce RTX 5080`。
若报 `uv trampoline failed to spawn Python child process`，说明修复脚本没生效，
不要继续往下走。

## 3. 模型权重

需要 5 个文件，放在 `runtime\ComfyUI\models\` 下对应子目录：

| 角色 | 目录 | 文件名 | 大小 |
|---|---|---|---|
| 扩散主模型 | `diffusion_models` | `minimax_h3_fl2va_pruned_nvfp4.safetensors` | 11.7 GB |
| 文本编码器 | `text_encoders` | `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` | 14.6 GB |
| 视频 VAE | `vae` | `minimax_h3_video_vae_fp16.safetensors` | 4.85 GB |
| 音频 VAE | `vae` | `minimax_h3_audio_vae_fp32.safetensors` | 0.56 GB |
| Turbo LoRA | `loras` | `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` | 1.82 GB |

若随项目一起拷贝，跳过本步。若要重新下载，**用 ModelScope 并绕开本地 7890 代理**——
魔搭有国内 CDN 节点，走代理反而更慢：

```powershell
$env:HTTP_PROXY=""; $env:HTTPS_PROXY=""
$env:NO_PROXY="modelscope.cn,www.modelscope.cn,modelscope.oss-cn-beijing.aliyuncs.com"
.\runtime\venv\Scripts\python.exe -m pip install modelscope
.\runtime\venv\Scripts\python.exe -m modelscope download --model <模型ID> --local_dir runtime\ComfyUI\models
```

**验证：**下载后务必核对字节数，不要只看文件存在。历史上出现过两个下载器写同一个
目标文件、大小正确但内容损坏，结果生成出彩色马赛克。

```powershell
.\runtime\venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'.');from orchestrator import config;print([m.filename for m in config.missing_models()] or 'OK')"
```

## 5. 启动与验收

双击项目根目录的 `启动.bat`，或：

```powershell
.\runtime\venv\Scripts\python.exe -m orchestrator.server
```

浏览器打开 <http://127.0.0.1:8801>。

**验收清单（逐条确认）：**

```powershell
# 1) 自检：硬件识别、模型齐备、启动参数
.\runtime\venv\Scripts\python.exe scripts\doctor.py

# 2) 端到端冒烟：起进程 -> 校验工作流 -> 出一张图 -> 停进程
.\runtime\venv\Scripts\python.exe scripts\smoke_test.py --profile draft
```

`doctor.py` 应显示 `注意力后端 ck`（驱动 ≥580 时）。若显示 `pytorch` 并附带
驱动提示，说明第 0 步的驱动条件没满足，速度会打折。

`smoke_test.py` 成功的标志是最后打印出 PNG 路径，且**打开图片确认画面连贯**——
能生成文件不等于生成对了内容。

## 6. 生产机调优

程序会按硬件自动选参（`orchestrator/hardware.py`），16GB 显存 + 64GB 内存的机器
预期得到：

```
--reserve-vram 0.5 --use-ck-attention --fast fp16_accumulation autotune
--high-ram --cache-ram 10 --async-offload 2
```

与开发机（12GB/32GB）的差异：生产机内存足够常驻权重，因此启用 `--high-ram`
而**不启用** `--fast-disk`；显存更宽裕，预留值从 0.9 降到 0.5。

**进一步提速（按收益排序）：**

1. **驱动升到 580+**（若尚未）。解锁 CK/NVFP4 加速内核。
2. **PyTorch 换 cu130 版**。ComfyUI 启动时若仍打印
   `You need pytorch with cu130 or higher to use optimized CUDA operations`，
   说明还在 cu128：

   ```powershell
   .\runtime\venv\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cu130 --upgrade torch torchvision torchaudio
   ```

   换版本后**重跑 smoke_test 确认没退化**，再用 `scripts\compare.py` 记录新基线。
3. **用 `scripts\compare.py` 定档**，不要凭感觉：

   ```powershell
   .\runtime\venv\Scripts\python.exe scripts\compare.py --variants draft,standard,quality --steps 8
   ```

   它会在一次模型加载内跑完所有变体，并按「每步每千 token 耗时」归一化，
   便于跨机器比较。

## 7. 常见故障与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `uv trampoline failed to spawn Python child process` | venv 绝对路径未修复 | 重跑第 2 步 |
| 采样中途 `CUDA driver version is insufficient` | 驱动 <580 但强制用了 CK 内核 | 升驱动，或让程序自动回退 |
| 端口 8801/8188 被占用 | 上次未正常退出 | 结束残留进程；或设 `LIBLOCAL_PORT` 换端口 |
| 生成出彩色马赛克 | 权重文件损坏 | 按第 3 步重新下载并核对字节数 |
| 显存不足 | 分辨率过高 | 降档位；或在面板点「释放显存」后重试 |
| 首次生成很慢 | 冷加载 ~28GB 权重 | 正常；后续同参数会命中缓存 |

日志位置：`data\logs\`。ComfyUI 的完整输出在 `comfyui-*.log`，
界面里的「本地运行时 → 查看日志」看的是同一份。

## 8. 远程调试（交给我部署时）

需要我远程接手时，请提供其中一种通道：

- **SSH**（推荐）：Windows 自带 OpenSSH Server，开启后给出地址与账号；
- 或 **远程桌面 + 一个可执行命令的终端**。

接手后我会按顺序做：`doctor.py` 自检 → `smoke_test.py` 冒烟 →
`compare.py` 定档 → 视频真机实测 → 把该机器的基线数据写入
`docs\性能基线.md`。

## 附：目录结构

```
Liblocal\
├─ 启动.bat                 一键启动
├─ orchestrator\            后端：进程/任务/工作流编排（Python，无额外依赖）
├─ PinCanvas\               前端画布（构建后产物在 dist\）
├─ runtime\                 自包含运行时
│  ├─ python\               独立 CPython 3.12
│  ├─ venv\                 依赖环境（含 torch）
│  └─ ComfyUI\              ComfyUI v0.34.0 + models\
├─ scripts\                 doctor / smoke_test / compare / repair-runtime
├─ data\                    输出、输入、日志、状态（可随时清理）
├─ h3lite\                  参考：H3 部署与提示词知识库
└─ docs\                    本文档等
```
